💻 What Is Claude Code — Talk to It First

Claude Code is a command-line tool — you run it in a terminal, it sees your files, and you have a conversation about what to build. The key difference from Claude.ai: it can read your project files, run code, and write to files directly. You're the architect. It's the builder.

claude > I'm a business student learning to build AI applications. I have 2 weeks of medical billing domain knowledge but I've never written Python. I'm going to direct you to build a Streamlit dashboard for medical claim data. Before we start: explain what you can and can't do, what makes a good instruction from me, and what I should do when I don't understand code you produce.
> What Python concepts will come up most often in this project — data loading, metrics, charts, and a web dashboard? Give me a plain-English overview of each, with no code yet.
💡 Notice: you're asking Claude Code to teach you before asking it to build. This is the correct order. Never ask it to build something you can't describe precisely.

💻 The Scaffold Directive — Give Claude Code This
I'm building ClaimPulse — a Streamlit dashboard for medical claim data analysis. The project needs to load a CSV with columns: claim_id, service_date, payer_name, cpt_code, icd_code, billed_amount, status, denial_reason. It will compute 7 KPIs: denial rate, days in A/R, $ at risk, clean claim rate, and 3 others. It will display 6 Plotly charts and AI-generated daily briefings using the Claude API. Please scaffold the complete project structure: all folders, all Python file stubs with docstrings, a requirements.txt with the libraries we'll need, a .gitignore, and a professional README.md. Create placeholder functions — don't implement them yet, just define the signatures and docstrings. I want to understand the architecture before any real code is written.
💡 Key principle: ask for architecture before implementation. Once you understand the structure, you can direct specific builds week by week. Jumping straight to "build it" produces code you don't understand.
✅ Review Every File Claude Code Creates — Before Committing
Does the folder structure match the requirements from Week 1? Are src/, data/, docs/, tests/ folders present?
Does requirements.txt include: pandas, plotly, streamlit, anthropic? Ask Claude Code to explain any library you don't recognise.
Does each Python file have a clear docstring explaining what it will do? Read every docstring out loud — if you can't understand it, ask Claude Code to rewrite it.
Does the README accurately describe the project and explain how to run it?
Never commit code you haven't read. Ask Claude Code to explain any line you don't understand.

In src/data_loader.py, write a function called load_data(filepath) that loads the claims CSV using pandas and returns a cleaned DataFrame. ✅ Code Review Checklist — Run This on Every Claude Code Output
Read every line out loud. If you can't say what it does, ask Claude Code: "What does line X do? Explain it like I'm new to Python."
Ask: "Why did you choose this approach? What are 2 other ways you could have done this?" Understanding alternatives builds genuine comprehension.
Run the script. If there's an error, paste the full error message back to Claude Code — don't guess at fixes.
After it works: could you delete it and rewrite it from memory? If not, ask more questions before moving on.
